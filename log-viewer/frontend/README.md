# Log viewer frontend

React + Vite frontend for browsing the MariaDB-backed request/pipeline logs produced by the bot.

## Stack

- React 19
- TypeScript
- Vite
- Tailwind CSS
- React Router
- Axios
- Socket.IO client
- Vitest

## What the app does

- provides a login screen
- stores auth state in session storage
- lists recent logs
- opens per-log detail pages
- listens for realtime log updates over Socket.IO
- proxies media through the backend when necessary

## Scripts

```bash
npm run dev
npm run build
npm run lint
npm run test
npm run preview
```

## Environment variables

- `VITE_PORT` - dev server port, default `5173`
- `VITE_PREVIEW_PORT` - preview server port, default `4173`
- `VITE_API_URL` - backend API base URL, default `/api`
- `VITE_SOCKET_URL` - Socket.IO base URL, default `/`
- `VITE_BACKEND_PROXY_TARGET` - Vite dev proxy target, default `http://backend:3001`
- `VITE_DISCORD_GUILD_ID` - optional guild ID used by Discord-related UI helpers

## Local development

### Inside the repo's Docker dev stack

This is the primary intended workflow for this repo:

```bash
docker compose --env-file .env.development up --build frontend backend db
```

The Vite dev server will be available on `http://localhost:5173` by default.

### Standalone frontend development

If you run the frontend outside Docker, make sure the backend is reachable and set at least:

```bash
VITE_API_URL=/api
VITE_SOCKET_URL=/
VITE_BACKEND_PROXY_TARGET=http://localhost:3001
```

## Backend expectations

The frontend expects the backend to provide:

- `POST /api/login`
- `GET /api/logs`
- `GET /api/logs/:id`
- media proxy routes under `/api`
- Socket.IO realtime updates

It also expects the backend to enforce auth and to read the same MariaDB log data generated by the Python app.
